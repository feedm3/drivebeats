# Bounded metadata Range endpoint

The metadata reader uses `POST /api/auth/drive-range` for sparse audio bytes. Google returned valid `206` responses in the authenticated browser probe but did not expose `Content-Range` to browser JavaScript. The approved same-origin endpoint makes that validation possible without a full-file fallback.

The browser still owns Library membership validation, priorities, cross-tab transport coordination, deadlines, request/byte allowances, tag parsing, and account/version-scoped local persistence. `loadedVia: drive_range` describes the byte source. Extracted tags remain browser-local and are never uploaded to this endpoint or Neon. Audio bytes are held in bounded server memory only for the duration of one request.

The endpoint accepts a strict JSON object containing `accountId`, `fileId`, `start`, `end`, and known total `size`. Input is capped at 4 KiB; spans are explicit safe integers within the known file size and at most 1 MiB. It requires a same-origin Origin header, rejects non-same-origin Fetch Metadata, checks the signed session and Drive scope, and uses the HttpOnly refresh cookie scoped to `/api/auth`. It refreshes OAuth server-side and verifies the refreshed Google userinfo `sub` against the signed account before making one media GET. Token refresh and userinfo are additional non-Drive provider requests. Tokens are not cached durably or returned to this endpoint's caller.

A combined 12-second deadline covers input, refresh, identity verification, Google headers, and body consumption. The media read uses only the static Google Drive endpoint, follows no redirects, requires exact `206`/`Content-Range` agreement, and bounds actual body consumption. Unexpected full responses, mismatched or truncated ranges, excess bodies, cancellation, and deadlines do not return audio as a successful range. There are no server retries, file mutations, full-file fallbacks, media persistence, or application logs of credentials, URLs, audio, or tags. Provider errors are sanitized; rate-limit status and valid Retry-After remain available to browser coordination. Genuine Drive limits carry `X-DriveBeats-Cooldown-Scope: drive`. OAuth/userinfo limits and unmarked endpoint or platform limits pause metadata only, preserving direct Drive playback/navigation. Endpoint sign-in/setup failures pause the metadata queue without changing browser playback authentication.

The browser schedules each proxy attempt through the existing Drive scheduler; a successful attempt performs exactly one upstream Drive media GET. An attempt rejected before that step may reserve an allowance conservatively. The server enforces the user's Google app-accessible file capability. Library ancestry remains a browser-local proof, rather than a server-enforced boundary. Browser coordination does not constitute a server-wide abuse or concurrency limit. Disconnect cancellation must be checked on the deployed host; the fixed deadline remains the fallback bound. The original direct-browser CORS failure and the endpoint's unit tests are distinct from real-host end-to-end evidence.
