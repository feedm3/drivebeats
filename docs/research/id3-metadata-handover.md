## Product direction

Build one account- and content-version-scoped browser-local metadata cache and search index used by the ordinary UI, playback and page WebMCP. There must be no agent-specific cache or separate remote MCP implementation.

- Automatically enrich visible tracks first, then the current folder and remaining proven Library, in throttled resumable background slices. Work must start even if the user never searches and no agent calls a tool.
- Ordinary users do not manage indexing. Keep UI changes minimal: at most a subtle activity indicator, with counts/reasons in a small panel on click. No setup dialogue, new index-management page, per-folder start controls or widespread row spinners.
- Use cached title/artist/album plus filename for local search; search itself must not trigger media downloads. Keep actual tags separate from filename/folder-derived display text.
- Page WebMCP exposes cached metadata in existing track outputs, a bounded known-ID metadata load tool and precise coverage/progress in status. Agents may use partial results while honestly reporting incomplete coverage.
- Target extracted tags to local storage only. Retire the existing Neon tag-sync mechanism in a staged change once product work is authorized. The shared `track_metadata` table serves both Favorites and Playlists. Collections still sync with file references/descriptors; removing this table does not remove all song-related information from the backend.
- Explain the tradeoff accurately: a fresh browser rebuilds its tags and initially displays filenames; after explicit logout/storage eviction it must rebuild again. Existing local audio/cache can serve tags offline; a fresh offline browser cannot fetch them.

## Technical decisions from review

1. **Catalog lifecycle:** after authenticated account/import hydration, when visible and online, explicitly ensure the existing complete account/import catalog. Reuse matching persisted generations, share a single build, refresh on scope invalidation or the existing 24-hour staleness cadence. Its current implementation lists accessible supported audio and folders before proving imported ancestry locally; automatic startup therefore deliberately initiates this metadata listing without a search. Budget every background list page. A waiting user/agent search promotes the SAME build within a bounded foreground request allowance, without resetting provider cooldown or spawning another build; on deadline return library_indexing with progress and detach the foreground consumer. Publish only complete generations; Library total stays unknown until then. Existing catalogs above 16 MiB or failed persistence remain session-only and require a controlled rebuild on reopening.
2. **Persistent outcomes:** ready, confirmed no-target-tags, or unresolved with reason, file/parser/policy version and scope. Unsupported formats, oversize tags and deterministic parser failures must survive reload without repeated reads. Host Range/CORS failures need environment-aware invalidation. Never classify transient errors or partial reads as tagless. MP3 classification uses original MIME/extension, not the synthetic MPEG fallback in the collection converter.
3. **Transport:** initially one coordinated Drive transfer per account/browser profile across callers/tabs, held until body consumption or cancellation. Prioritize actual playback. Direct uncached navigation can preempt cancellable full-file prefetch/offline work so it does not wait behind a large audio body. Do not interrupt the current playback download for metadata. Offline transport throughput intentionally changes from two simultaneous files to one at this initial setting. Start offline header/body timers only when granted transport, not during queue wait; a dedicated preempted outcome requeues without spending a failure attempt or error backoff, while already transferred bytes still count. Test repeated navigation and queue waits longer than 30 seconds without permanently failing a download.
4. **Cross-tab and rate state:** atomically share/persist budget windows, reservations, provider cooldown and leader fencing, using appropriate browser coordination. A 429 in tab A must delay reads in tab B; reload cannot reset the cooldown/budget. If durable shared coordination is unavailable, pause automatic whole-Library work and report degraded coverage rather than spawning independent scanners. Bound direct reads locally. A hidden leader relinquishes its automatic-work lease to a visible tab using a new fencing generation; all-hidden means pause. Other profiles/devices are independent, so this cannot guarantee absence of provider limits.
5. **Range reader:** reuse already available playback/offline Blobs first; otherwise use an authenticated bounded custom jsmediatags MediaFileReader. Verify 206, Content-Range and body limits; abort unexpected full responses instead of consuming full audio. Retain the installed parser initially. Its text-only field filter still requests the whole ID3v2 tag including embedded cover data. MP3 is the first remote adapter; other formats remain explicitly unresolved unless an available Blob can be parsed.
6. **Search stability:** immutable bounded result snapshots with opaque continuation cursors, frozen tag values/observed time and account/query binding. Normal metadata warming must not invalidate a paginated search. Proposed snapshot bounds: 2-minute absolute TTL, 4 snapshots/account, 50,000 total retained result rows and 16 MiB; clear restart/restriction errors on eviction/oversize/scope changes. Retain legacy offset calls as unversioned individual searches. Existing UI selection and multi-page reading must remain stable.
7. **Coverage:** disjoint ready/noTargetTags/unresolved/stale/transient-errors/unknown buckets over the proven complete Library. checked = ready + noTargetTags; remaining = stale + transient-errors + unknown; unresolved counts are separate with reasons. Map current ready/no_target_tags/unresolved to their buckets, transient error to errors, and missing/deferred/queued/loading to unknown; a stale fingerprint takes precedence, while a current ready result stays ready even if another job exists. A foreign/unproven unavailable ID is outside the denominator; a proven member with revoked file access stays represented as an error/unresolved. Before the complete catalog, total/remaining are null. Finishing all possible work with unresolved tracks is partial with remaining 0, not complete or perpetual loading.

Provisional limits, to calibrate rather than present as provider guarantees: 1–10 unique known IDs per tool, 15-second maximum tool deadline including queueing, 1 MiB/track and 4 Range attempts, up to 2 descriptor-check attempts, 2 MiB/20 actual Drive GET attempts per explicit batch. Background slices: 5 MiB/50 attempts, at most one background GET/second, refill no earlier than two minutes and after any longer provider cooldown. Reserve/count retries; render/navigation/tool calls do not reset budgets. See the detailed plan for exact failure and cancellation semantics.
